### 一、核心概念定义

#### 1.1 三层实体模型
```plaintext
┌─────────────────────────────────────────────────────────────────┐
│                      评测库 (Image Pairs)                        │
│                                                                 │
│  系统中所有待评测的图像对集合，动态增长                            │
│  · 管理员按场景导入，每个场景包含多个设备的图片                     │
│  · 设备间自动组合成图对 (C(n,2))                                 │
│  · 时刻 T1: 90 对 ──新增──→ 时刻 T2: 140 对 ──新增──→ ...       │
│  · 用户视角 = "系统中有多少对等着我评"                             │
│                                                                 │
│  关键属性：场景归属、设备型号、图片路径、排序权重                   │
└──────────────────────────────────┬──────────────────────────────┘
                                   │
                     为用户分配未评对（按场景分组）
                                   │
                                   ▼
┌─────────────────────────────────────────────────────────────────┐
│                  评测会话 (Evaluation Session)                    │
│                                                                 │
│  一次"坐下来评测"的完整经历，是进度管理和状态恢复的基本单位         │
│  · 每次开始评测时创建一个 Session                                 │
│  · 系统从评测库中分配一批未评图对给该 Session                      │
│  · Session 内的图对列表在创建时确定，中途不变                      │
│  · 用户中途退出后，下次可恢复到同一 Session 继续                   │
│                                                                 │
│  关键属性：                                                      │
│  ┌──────────────┬─────────────────────────────────────────────┐ │
│  │ id           │ 会话唯一标识                                 │ │
│  │ user_id      │ 所属评图员                                   │ │
│  │ status       │ active / completed                          │ │
│  │ pair_ids     │ 本会话分配的图对 ID 列表（JSON，有序）        │ │
│  │ batch_size   │ 本会话分配的对数                             │ │
│  │ started_at   │ 会话开始时间                                 │ │
│  │ completed_at │ 会话完成时间（提交后填写）                    │ │
│  └──────────────┴─────────────────────────────────────────────┘ │
└──────────────────────────────────┬──────────────────────────────┘
                                   │
                         每对逐一评分（草稿机制）
                                   │
                                   ▼
┌─────────────────────────────────────────────────────────────────┐
│                     评分记录 (Evaluation)                         │
│                                                                 │
│  用户对单个图对的主观评价，存在两种状态                            │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │  draft (草稿)                                            │    │
│  │  · 用户评分后立即创建，可修改，可覆盖                      │    │
│  │  · 前后导航回看时可以看到自己的选择                         │    │
│  │  · 不参与最终统计计算                                     │    │
│  │  · 同一用户+同一图对只能有一条 draft 记录（UPDATE 覆盖）   │    │
│  ├─────────────────────────────────────────────────────────┤    │
│  │  submitted (已提交)                                      │    │
│  │  · 用户点击"提交结果"后，当前 Session 所有 draft 批量转换   │    │
│  │  · 不可修改，不可撤销                                     │    │
│  │  · 参与最终统计计算                                       │    │
│  │  · submitted_at 记录提交时间                              │    │
│  └─────────────────────────────────────────────────────────┘    │
│                                                                 │
│  关键属性：                                                      │
│  ┌──────────────┬─────────────────────────────────────────────┐ │
│  │ id           │ 记录唯一标识                                 │ │
│  │ user_id      │ 评图员                                       │ │
│  │ pair_id      │ 图像对（user_id+pair_id 唯一约束）           │ │
│  │ session_id   │ 归属会话                                     │ │
│  │ score        │ 评分键值 (a_much / a_slight / same / ...)   │ │
│  │ status       │ draft / submitted                           │ │
│  │ created_at   │ 首次评分时间                                 │ │
│  │ submitted_at │ 提交时间（draft 时为 null）                  │ │
│  └──────────────┴─────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```
#### 1.2 批次大小
参考依据：ITU-R BT.500 建议书 & 学术界 Image Quality Assessment 实验惯例

| **参数**   | **值** | **依据说明**                                                   |
| -------- | ----- | ---------------------------------------------------------- |
| 默认批次大小   | 40    | 按 10～30s / 对测算，单轮耗时约 6.66～20 分钟，贴合 ITU 单轮最优时长区间，兼顾效率与评测稳定性 |
| 最大批次大小   | 45    | 超过 45 对后，即便画面简单，连续专注度也会明显下降，控制疲劳边界                         |
| 剩余不足默认值时 | 全部    | 剩余不足 40 对则一次性分配完毕，不拆小批次                                    |
| 单日建议上限   | 100   | 单对耗时变短，合理提升单日软上限，避免频繁中断                                    |
| 连续批次休息建议 | 3 轮后  | 每连续完成 3 个批次，弹窗提示休息，可跳过不强制                                  |
配置项统一放在 config.py，管理员可调整，用户不可自选。
#### 1.3 分配策略
```
为用户分配未评图对时遵循以下原则：

1. 排除已评图对
   无论历史评分是 draft 还是 submitted，
   只要该用户对某图对有记录，就不再分配。
   原因：draft 记录也代表用户已经看过并做出了判断，
   重新看同一对会引入记忆偏差。

2. 按场景分组
   同一场景的图对尽量放在同一批次，
   减少场景切换带来的上下文切换成本。

3. 场景内按排序权重
   同一场景内的图对按 sort_order 排序，
   保证所有评图员看到的顺序一致，
   便于后续交叉验证。

4. 分配结果在创建 Session 时固化
   pair_ids 写入 Session 记录，中途不变。
   即使管理员新增了图对，也不影响当前进行中的 Session。

5. 重复图对分配
   每轮分配时：
   - 从剩余未评图对中选取 new_pair_count 个新图对
   - 按比例计算重复图对数：repeat_count = max(0, int(new_pair_count * REPEAT_RATIO))
   - 从新图对中随机选取 repeat_count 个作为重复图对
   - pair_ids = 新图对 + 重复图对
   - batch_size = new_pair_count + repeat_count

   示例（REPEAT_RATIO=0.1）：
   - 剩余 200 对 → 40 新 + 4 重复 = 44 次评测
   - 剩余 30 对 → 30 新 + 3 重复 = 33 次评测

```

#### 1.4 重复图对配置

| 参数 | 配置项 | 值 | 说明 |
|------|--------|-----|------|
| 重复图对比例 | REPEAT_RATIO | 0.1 (10%) | 每轮分配时，从新图对中随机选10%作为重复图对 |
| 重复图对用途 | - | - | 用于计算重测信度，衡量用户评分一致性 |

### 二、状态模型

#### 2.1 用户状态机
```
                         ┌──────────────┐
                         │   LOADING    │ ← 页面初始化，拉取状态
                         └──────┬───────┘
                                │
                    ┌───────────▼────────────┐
                    │  GET /api/eval/status  │
                    └───────────┬────────────┘
                                │
              ┌─────────────────┼──────────────────┐
              │                 │                  │
       total_pairs=0    has_active_session    无 active session
              │          +remaining>0          +remaining>0
              │                 │                  │
       ┌──────▼──────┐ ┌──────▼──────┐   ┌───────▼────────┐
       │  NO_PAIRS   │ │  RESUMABLE  │   │ READY_TO_START │
       │ "暂无数据"   │ │ "继续评测"  │   │ "开始评测"     │
       └─────────────┘ └──────┬──────┘   └───────┬────────┘
                               │                  │
                    点击"继续"  │     点击"开始"   │
                               ▼                  ▼
                         ┌──────────────────────────┐
                         │       IN_SESSION          │
                         │   正在评测（逐对展示）     │
                         │   顶栏: 8/20 进度条       │
                         └────────┬─────────────────┘
                                  │
                    ┌─────────────┼──────────────┐
                    │             │              │
              中途退出      Session 内全评完   Session 内全评完
              (关闭页面)    +无更多未评对      +还有未评对
                    │             │              │
                    ▼             ▼              ▼
             ┌──────────┐ ┌───────────┐  ┌──────────────┐
             │ RESUMABLE│ │ ALL_DONE  │  │BATCH_COMPLETE│
             │(下次继续) │ │"全部完成" │  │"本轮完成"    │
             └──────────┘ └───────────┘  │ +可开始新批次 │
                                         └──────────────┘

```
#### 2.2 五种状态定义

| 状态                 | 含义                | 前端展示                                 | 用户可执行动作      |
| ------------------ | ----------------- | ------------------------------------ | ------------ |
| **LOADING**        | 正在拉取用户评测状态        | 加载动画（已有的 spinner）                    | 无            |
| **NO_PAIRS**       | 系统中无图像对           | “暂无评测数据，请等待管理员添加”                    | 退出、刷新        |
| **READY_TO_START** | 有未评对，无进行中会话       | “您有 N 对图像待评测” + [开始评测]               | 开始评测、退出      |
| **RESUMABLE**      | 有进行中会话，未评完        | “您有一轮评测进行中（已评 M/N）” + [继续评测]         | 继续评测、退出      |
| **IN_SESSION**     | 正在评测中             | 图像对 + 评分按钮 + 进度条 + 导航                | 评分、前后导航、退出   |
| **BATCH_COMPLETE** | 当前批次全部评分（草稿），尚未提交 | “本轮评测完成” + 统计 + [提交结果] [再来一轮] [查看结果] | 提交、再来一轮、查看结果 |
| **ALL_DONE**       | 所有图像对均已评价并提交      | “全部完成，感谢参与” + [查看结果]                 | 查看结果、退出      |
#### 2.3 状态转换触发条件
```
LOADING ──(API返回)──→ NO_PAIRS / READY_TO_START / RESUMABLE / ALL_DONE

READY_TO_START ──(点击"开始评测")──→ IN_SESSION
  └── POST /api/eval/start-session
  └── 后端创建新 Session，分配图对

RESUMABLE ──(点击"继续评测")──→ IN_SESSION
  └── POST /api/eval/resume-session
  └── 后端返回 Session 中所有图对 + 已有草稿

IN_SESSION ──(Session 内所有图对都已评分)──→ BATCH_COMPLETE / ALL_DONE
  └── 若剩余未评对数 > 0 → BATCH_COMPLETE
  └── 若剩余未评对数 = 0 → ALL_DONE（跳过 BATCH_COMPLETE，直接可提交）

IN_SESSION ──(中途退出/关闭页面)──→ RESUMABLE
  └── 下次进入时 /api/eval/status 检测到 active Session

BATCH_COMPLETE ──(点击"提交结果")──→ ALL_DONE 或 回到 BATCH_COMPLETE
  └── POST /api/eval/submit-round
  └── 若提交后 remaining > 0 → 仍显示 BATCH_COMPLETE（可"再来一轮"）
  └── 若提交后 remaining = 0 → ALL_DONE

BATCH_COMPLETE ──(点击"再来一轮")──→ READY_TO_START → IN_SESSION
  └── 检查是否达到休息建议 → 创建新 Session

ALL_DONE ──(管理员新增图片对)──→ READY_TO_START
  └── 下次进入时 remaining > 0，status 变为 ready

```
#### 2.4 后端 status 判定逻辑
```
GET /api/eval/status 的后端判定流程：

1. total_pairs = SELECT COUNT(*) FROM image_pairs
   IF total_pairs == 0 → return "no_pairs"

2. evaluated_count = SELECT COUNT(*) FROM evaluations
                     WHERE user_id = ? AND status = 'submitted'
   remaining_count = total_pairs - evaluated_count
   IF remaining_count == 0 → return "all_done"

3. active_session = SELECT * FROM eval_sessions
                    WHERE user_id = ? AND status = 'active'
   IF active_session EXISTS:
     draft_in_session = SELECT COUNT(*) FROM evaluations
                        WHERE user_id = ? AND session_id = ? AND status = 'draft'
     IF draft_in_session < active_session.batch_size:
       → return "resumable"（会话中还有未评的）
     ELSE:
       → 会话内全评完了但还没提交
       → 视同 IN_SESSION 尾声，前端显示提交按钮
       → return "resumable"（让前端恢复到 IN_SESSION 状态）

4. 以上都不满足 → return "ready"
```
### 三、整体交互流程设计逻辑

#### 3.1 核心原则
```
原则 1：后端是状态真相的唯一来源
  前端不做状态推断，所有状态转换由后端 /api/eval/status 的返回值驱动。
  前端的职责：渲染 UI + 转发用户操作到后端。

原则 2：草稿可改，提交锁定
  评分 → draft（可覆盖修改）
  提交 → submitted（不可逆）
  前后导航回看时，已评草稿显示选中态，可重新打分覆盖。

原则 3：一次加载，前端导航
  start-session / resume-session 返回当前 Session 的全部图对列表。
  前端 pairList 缓存完整列表，scoreMap 缓存所有草稿，
  导航操作纯前端完成，不需要逐个请求后端。

原则 4：评分即存，不怕丢失
  每次评分立即 POST /api/eval/submit（draft），
  中途退出不丢数据，刷新页面可恢复。

原则 5：批次控制，疲劳管理
  每轮默认 20 对，连续 2 轮后建议休息（可跳过）。
  保证评测质量，同时不强制中断用户。
```
#### 3.2 完整生命周期
```
用户 A 的评测历程（示例）：

Day 1
  登录 → /api/eval/status → ready (90 对待评)
  点击"开始评测" → POST /start-session → Session 1 (20对)
  评了 12 对后关闭浏览器

Day 2
  登录 → /api/eval/status → resumable (Session 1: 12/20)
  点击"继续评测" → POST /resume-session → 恢复到第 13 对
  评完剩余 8 对 → BATCH_COMPLETE
  点击"提交结果" → POST /submit-round → Session 1 锁定
  显示"还有 70 对待评" → 点击"再来一轮"
  → POST /start-session → Session 2 (20对)
  评完 20 对 → BATCH_COMPLETE → 提交

Day 3
  登录 → /api/eval/status → ready (50 对待评)
  提示"您已连续完成 2 轮，建议休息"（可跳过）
  开始 Session 3 (20对) → 评完 → 提交

Day 5
  管理员新增 30 对图对
  登录 → /api/eval/status → ready (60 对待评，含 30 对新增)
  显示"有 30 对新图像待评测"
  开始 Session 4 (20对) → ...

直到 remaining = 0 → ALL_DONE
```
### 四、后端 API 设计

#### 4.1 API 总览

|API|Method|说明|调用时机|
|---|---|---|---|
|`/api/eval/status`|GET|获取当前评测状态|页面初始化|
|`/api/eval/start-session`|POST|创建新评测会话|点击"开始评测"|
|`/api/eval/resume-session`|POST|恢复进行中的会话|点击"继续评测"|

#### 4.2 GET /api/eval/status

```
请求：GET /api/eval/status
响应：

{
  "total_pairs": 90,                    // 系统中图像对总数
  "evaluated_count": 20,                // 该用户已提交总数
  "remaining_count": 70,                // 该用户未评总数（含草稿未提交的）

    "remaining_in_session": 8           // Session 内未评数
  },

  "new_pairs_count": 30,                // 自上次提交后新增的对数
  "daily_evaluated": 40,                // 今日已评数量
  "suggest_rest": false                 // 是否建议休息

```

#### 4.3 POST /api/eval/start-session
```
请求：POST /api/eval/start-session
（无请求体，批次大小由后端 config 决定）

后端逻辑：
1. 检查是否有活跃会话 → 有则返回 409
2. 查询用户未评图对（evaluations 中无记录的）
3. 按场景分组，取前 new_pair_count 个新图对
4. 计算重复图对数：repeat_count = max(0, int(new_pair_count * REPEAT_RATIO))
5. 从新图对中随机选取 repeat_count 个作为重复图对
6. pair_ids = 新图对 + 重复图对（随机打乱顺序）
7. 创建 Session 记录，写入 pair_ids
8. 返回 Session 信息 + 全部图对列表

响应：
{
  "session_id": 5,
  "batch_size": 20,
  "pairs": [
    {
      "pair_id": 3,
      "scene_name": "室内-客厅",
      "image_a_url": "/uploads/images/xxx.jpg",
      "image_b_url": "/uploads/images/yyy.jpg",
      "my_score": null               // 新 Session，全部为 null
    },
    {
      "pair_id": 7,
      "scene_name": "室内-客厅",
      "image_a_url": "...",
      "image_b_url": "...",
      "my_score": null
    },
    // ... 共 20 个
  ]
}
```

#### 4.4 POST /api/eval/resume-session

```
请求：POST /api/eval/resume-session
（无请求体，后端自动查找用户的 active session）

后端逻辑：
1. 查找用户的 active Session
2. 加载 Session.pair_ids 中所有图对的详情
3. 查询这些图对中已有的 draft 记录
4. 计算下一个未评对的游标位置

响应：
{
  "session_id": 3,
  "batch_size": 20,
  "pairs": [
    {
      "pair_id": 3,
      "scene_name": "室内-客厅",
      "image_a_url": "...",
      "image_b_url": "...",
      "my_score": "a_much"           // 已有草稿
    },
    {
      "pair_id": 7,
      "scene_name": "室内-客厅",
      "image_a_url": "...",
      "image_b_url": "...",
      "my_score": null               // 尚未评分
    },
    // ...
  ],
  "next_cursor": 5                   // 下一个 my_score=null 的索引
}
```

#### 4.5 POST /api/eval/submit

```
请求：
{
  "pair_id": 3,
  "session_id": 5,
  "score": "a_much",
  "score_label": "A更好"
}

后端逻辑：
1. 判断该 pair_id 在当前 session 中是否已评测过
   - 检查是否存在 is_repeat=0 的记录（包括 draft 和 submitted）
   - 如果已有首次评测记录，则本次为 is_repeat=1（重复评测）
   - 如果没有，则本次为 is_repeat=0（首次评测）

2. 检查是否已存在相同的重复类型
   · 有 submitted 记录 → 返回 409 "该图对已提交，不可修改"

3. 处理评分记录
   · 无记录 → INSERT (status='draft', is_repeat=0 或 1)
   · 有 draft 记录 → UPDATE score 等字段

4. 返回评分确认

响应：
{
  "evaluation_id": 42,
  "status": "draft",                 // 始终是 draft，直到 submit-round
  "score": "a_much"
}
```

#### 4.6 POST /api/eval/submit-round

```
请求：
{
  "session_id": 5
}

后端逻辑：
1. 检查该 Session 是否属于当前用户
2. 检查该 Session 内所有图对是否都有 draft 评分
   · 有未评的 → 返回 400 "还有 N 对未评分"
3. 批量更新：UPDATE evaluations SET status='submitted', submitted_at=NOW()
   WHERE user_id=? AND session_id=? AND status='draft'
4. 更新 Session：status='completed', completed_at=NOW()
5. 重新计算 remaining_count
6. 返回统计摘要
```

### 八、重测信度计算

#### 8.1 功能说明

重测信度模块独立于盲评任务模块，用于衡量用户评分的一致性。通过比较同一图对的两次评测结果，判断用户是否认真评测。

**模块解耦原则**：
- 盲评任务模块：只负责记录评测结果，不关心信度计算
- 重测信度模块：独立服务，从数据库读取评测结果，计算一致性
- 通过定时任务或手动触发计算

#### 8.2 计算逻辑

1. 查找指定 session 中 is_repeat=1 的评测记录
2. 对每条重复评测，查找对应的首次评测（is_repeat=0）
3. 将两次评分映射为方向：
   - a_much / a_slight → "a_win"
   - same → "tie"
   - b_slight / b_much → "b_win"
4. 比较方向是否一致
5. 一致率 = 一致数 / 总重复对数

#### 8.3 阈值配置

| 参数 | 配置项 | 值 | 说明 |
|------|--------|-----|------|
| 重测信度阈值 | RETEST_THRESHOLD | 0.6 | 一致率 >= 0.6 为通过 |
