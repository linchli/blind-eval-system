## 1. 模块内部实体模型

本模块的核心实体为用户表（`users`），采用轻量级设计，结合无状态JWT令牌管理认证，不在数据库层维护Session信息。

### 1.1 用户表

| 字段名            | 类型           | 约束                            | 说明                                              |
| -------------- | ------------ | ----------------------------- | ----------------------------------------------- |
| id             | INT          | PK, AUTO_INCREMENT            | 主键                                              |
| username       | VARCHAR(50)  | UNIQUE, NOT NULL              | 登录用户名                                           |
| email          | VARCHAR(120) | UNIQUE, NOT NULL              | 邮箱（用于通知）                                        |
| password_hash  | VARCHAR(255) | NOT NULL                      | Argon2/bcrypt 加密后的密码哈希                          |
| role           | ENUM         | NOT NULL, DEFAULT ‘evaluator’ | 角色：`admin`(管理员), `evaluator`(评测员), `guest`(访客)  |
| display_name   | VARCHAR(100) | DEFAULT ‘’                    | 显示名称（前端展示用）                                     |
| status         | ENUM         | NOT NULL, DEFAULT ‘active’    | 账号状态：`active`(活跃), `frozen`(冻结), `inactive`(注销) |
| last_active_at | DATETIME     | NULL                          | 最后活跃时间（用于统计与清理）                                 |
| created_at     | DATETIME     | DEFAULT CURRENT_TIMESTAMP     | 创建时间                                            |

### 1.2 角色权限矩阵

|功能模块|操作|Admin (管理员)|Evaluator (评测员)|Guest (访客)|
|---|---|---|---|---|
|**图像管理**|场景/机型/图像的增删改|✅|❌|❌|
||触发图像配对|✅|❌|❌|
||查看图像元数据及机型绑定|✅|❌|❌|
|**盲评任务**|发起/继续评测会话|✅|✅|❌|
||提交评分|✅|✅|❌|
|**结果展示**|查看脱敏排行榜|✅|✅|✅|
||查看评分明细及机型对应关系|✅|❌|❌|

## 2. 模块内部的状态机

用户账号状态管理遵循极简原则，保证业务安全的同时降低维护复杂度。

### 2.1 用户账号生命周期
```mermaid
stateDiagram-v2
    [*] --> 活跃 : 管理员创建账号
    
    活跃 --> 冻结 : "管理员操作 (例如发现恶意刷分)"
    冻结 --> 活跃 : 管理员解冻
    
    活跃 --> 注销 : 用户主动申请注销
    冻结 --> 注销 : 管理员强制注销
    
    注销 --> [*]
    
    note right of 活跃
        可正常登录与评测
        last_active_at 随操作更新
    end note
    
    note right of 冻结
        无法登录，JWT失效
        已提交的历史评分保留（用于数据一致性计算）
    end note
    
    note right of 注销
        逻辑注销，非物理删除
        关联的 evaluations 保留
        账号信息脱敏处理
    end note
```
## 3. 模块内部的交互逻辑

### 3.1 认证与授权流程 (JWT无状态方案)

系统采用JWT（JSON Web Token）进行接口鉴权，避免在数据库中维护Session表，降低服务端状态同步压力。

```mermaid
sequenceDiagram
    participant Client as 前端客户端
    participant API as 后端网关/中间件
    participant UserSvc as 用户服务
    participant DB as 数据库

    Note over Client,DB: 1. 登录认证流程
    Client->>API: POST /api/auth/login {username, password}
    API->>UserSvc: 校验凭证
    UserSvc->>DB: SELECT * FROM users WHERE username=? AND status='active'
    DB-->>UserSvc: 返回用户信息
    UserSvc->>UserSvc: 校验 password_hash
    UserSvc-->>API: 返回用户数据 (id, role, display_name)
    API->>API: 生成 Access Token (有效期2h) & Refresh Token (有效期7d)
    API-->>Client: 返回 Tokens 及用户基本信息

    Note over Client,DB: 2. 业务请求鉴权流程
    Client->>API: GET /api/eval/sessions (Header: Authorization: Bearer <token>)
    API->>API: 中间件拦截，验证Token签名与有效期
    alt Token无效或过期
        API-->>Client: 401 Unauthorized
    else Token有效
        API->>API: 解析Token提取 user_id 和 role
        alt 权限不足 (如: Evaluator访问Admin接口)
            API-->>Client: 403 Forbidden
        else 权限校验通过
            API->>UserSvc: 继续处理业务逻辑
            UserSvc-->>API: 返回结果
            API-->>Client: 200 OK
        end
    end

```
